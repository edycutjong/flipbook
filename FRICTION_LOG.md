# Friction log — building Flipbook on Vega

Dated, first-hand entries from building Flipbook on the Vega SDK 0.24.12112 (Vega CLI 1.4.4) and the
Vega Virtual Device (VVD) on an Apple M-series Mac, macOS 26.5. Each entry: what happened, how long it cost,
what would have prevented it.

| # | Date | Area | What happened | Workaround / fix | Suggestion |
|---|---|---|---|---|---|
| 1 | 2026-10-12 | vega-video-sample docs | The sample's README asks for Node 18–20, its `package.json` says `engines.node >= 22`. We built with Node 20.20.2 + JDK 21 and it worked. | Pinned Node 20 + JDK 21 per shell. | One supported Node range in both places. |
| 2 | 2026-10-12 | Packager | A Vega project under any directory named `assets` builds a vpkg whose entries embed the host path; the app installs but hangs in "Creating surfaces" (ANR after ~15 s) or fails install with "Missing icon file". No error points at the path. ~90 min. | Build from a path with no `assets` component. | Fail the build with a clear message when the project path contains `assets/`. |
| 3 | 2026-10-12 | Home screen (sample) | Replacing the catalogue with ONE row of 2 tiles made the app hang at launch (ANR, "Creating surfaces"); two rows work. | Two rows: Matches + Witness. | Document minimum item counts for the carousel / grid, or handle short rows. |
| 4 | 2026-10-12 | W3C media player | `http://` media URIs are refused by the native player (`isUriSchemeSecure Got an insecure protocol/scheme http`), surfaced to JS only as a generic "Streaming Error". JS `fetch` and image loads over http work. | Serve the dev match as HLS played through Shaka (MSE), which fetches segments in JS. | Say "https required for URL sources" in the error the app receives. |
| 5 | 2026-10-12 | W3C media player | Loading an MP4 from the Internet Archive (302 redirect, slow first bytes, 5.6 MB `moov`) froze the JS thread ~8 s and LCM killed the app as ANR. | Local HLS instead. | Keep `load()` off the JS thread / time out without ANR. |
| 6 | 2026-10-12 | Amazon's sample BIF | `tv-webinar-hd.bif` stores `0xFFFFD8F0` in the timestamp-multiplier field; the sample parser multiplies it in (≈4.29e9 ms per frame) and only works because `getEndIndex` ignores the parsed times and assumes 10 s. The catalogue entry also says `duration: 190` for a 71-minute video. | Flipbook's `readBif` treats multipliers outside 1 ms–60 s as corrupt and derives the unit from the asset duration, else 10 s. | Fix the header of the hosted BIF; make the sample lookup use the parsed interval when it is sane. |
| 7 | 2026-10-12 | Sample BIF parser | A BIF without the `0xffffffff` terminator only logs a warning and the trailing offset is still trusted (corrupt last frame). | `readBif` rejects it ("No trickplay index for this title"). | Validate the final offset against `byteLength`. |
| 8 | 2026-10-12 | KUI SeekBar | `partialDisablingConfiguration={{ skipForward, skipBackward }}` and the `markers` prop are exactly what an app that owns FF/RW needs, but we found them by reading `dist/` — the sample uses neither. | Used both. | Show them in the sample. |
| 9 | 2026-10-12 | Logs | App `console.info` lines appear in `loggingctl log -f` only while a follower is attached, mixed with ~100 lines/s of system output; `-S -60s` is unsupported. | `loggingctl log -f -o short_precise` piped through grep. | A per-app log tail (`vega logs <pkg>`). |
| 10 | 2026-10-12 | VVD | After the Mac's screen locked, the running VVD stopped repainting the React Native layer (video kept playing), and a restarted VVD never booted: QEMU "hanging thread 'QEMU2 main loop'" after GPU init, also with `--no-gui` and on a fresh instance. | Unlock the Mac before using the VVD. | Detect a locked/asleep host display and say so; a software-GL fallback on macOS. |
| 11 | 2026-10-12 | Kiro Crew | `kirocrew run TASK.md` runs in its own workspace and, unattended, its write/shell tools were denied by the approval policy; it produced nothing in ~40 min and hit 429 `CREDIT_CONSUMPTION_RATE_EXCEEDED` 28 times. `kiro-cli chat --no-interactive --trust-all-tools` in the repo did the same task in ~3 min. | Used kiro-cli headless. | Let `kirocrew run` target an existing directory with a pre-approved tool policy. |
