How it works

Scan. Mark. Jump. On the device.

FLIPBOOKpre-release · 04 / 10
Everything runs on the device, with no server. The sample's BIF service downloads the file and hands us the raw bytes; our own parser checks the header, jpeg-js decodes each frame and we keep only the calibrated score box. Pass 1 samples every eighth frame and bisects where the box differs; pass 2 reads every frame and can only add. The KUI SeekBar draws the ticks and masks thumbnails; our key handler owns fast-forward.

The judged path uses four Vega platform surfaces, plus the sample's BIF service, which we extended to hand over the raw bytes. Verifying against Amazon's own file we found a timestamp-multiplier value that would break a binary search, so Flipbook's own parser sanity-checks the header. Eighteen friction-log entries document the rest; Kiro's CLI wrote the BIF writer and its tests.
