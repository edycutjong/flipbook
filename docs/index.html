What the detector sees

Three frames before, three after. It has to hold.

These are the actual pixels inside the calibrated box around the first change, unmasked. Flipbook never reads the digits: it shrinks the box to a 64×5 luma grid, takes the median of three present frames on each side, and fires only if the top-3 cell distance clears τ = 20. The marker sits on the anchor — the last frame that still shows the old score — and goes 30 s before it.

How it works

Scan. Mark. Jump. On the TV.

No backend, no feed, no model. A forked Amazon sample, a TypeScript detector with no UI dependencies, and four Vega platform surfaces.

The file the player already has

A BIF is a contact sheet of the whole match — one JPEG roughly every 10 s, downloaded so the seek bar can preview. Flipbook reads it as a corpus through Amazon's own BIF service from the sample, which we forked and fixed: Amazon's tv-webinar-hd.bif has 428 frames at 240×180 and a timestamp-multiplier field of 0xFFFFD8F0, so Flipbook sanity-checks the header and falls back to a 10 s interval.

BifParser0xFFFFD8F010 s fallback

Only the box

jpeg-js decodes each thumbnail on the device; only the calibrated rectangle becomes a 64×5 luma grid. Cells that jitter — the pitch showing through — are masked out.

jpeg-js 0.4.464×5

Two passes

Pass 1 reads every 8th frame and bisects only where the box differs: on the development match both ticks were up after 77 of 517 decodes. Pass 2 still reads all 517 and can only add.

stride 8bisect

It has to hold

Medians of three present frames on each side, so a replay wipe or a dropped graphic cannot fire. The anchor walks back over any graphic-absent run to the last old-score frame.

τ = 203-frame median

belongs to Flipbook

useTVEventHandler takes the skip keys and sets currentTime to anchor − 30 s. On the VVD the seek landed at 199.1 s and was still 199.1 s 1.5 s later: no OS seek stacked on top.

useTVEventHandlerpartialDisablingConfiguration

Thumbnails stay masked

The KUI SeekBar's displayAboveThumb draws film-base black over the score box on every scrub thumbnail; before calibration, thumbnails stay off. Blind mode is the default: no ticks, no counts, only how far the scan has read.

displayAboveThumbblind by default

Four Vega surfaces

  • VideoPlayer (W3C media) — playback; the jump sets currentTime
  • KUI SeekBar — markers for ticks, displayAboveThumb for the mask
  • useTVEventHandler, TVFocusGuideView — skip keys and calibration
  • Vega Virtual Device + CLI — build, run, on-device logs and captures

FAQ

Does it really decode no video?

Yes. Flipbook decodes only the BIF's thumbnail JPEGs, with jpeg-js. The bench reports videoBytesDecoded: 0 and the device log says video bytes decoded=0.

Did it run on a Fire TV?

On the Vega Virtual Device (Vega SDK 0.24.12112) on an Apple M-series Mac. No Fire TV hardware was available, so every timing says so. Some on-device captures are still owed — a calibrated scan of the development match among them — and the README lists them.

How good is it, really?

On the development match — two goals, labelled by the detector's author — it found 2 of 2 with 0 false markers, and both jumps landed before the play (95 % CI [0.158, 1]). That shows the pipeline works, not that it generalises.

The held-out number (goal jumps landing before the goal on match B) will exist only after a human labels matches A and B. The parameters are frozen in PREREG.json first.

Why not read the digits?

Trickplay thumbnails are tiny — Amazon's are 240×180 — so Flipbook detects that the box changed and held, not what it says. No OCR, no ML, no LLM: arithmetic on a calibrated rectangle.

Doesn't blind mode still give something away?

A little, and the README says so: a jump tells you a change lies ahead, "No later change" tells you none does, and a goal the detector missed is skipped without any sign.

Is the footage OK to use?

The three matches are Belmont Media Center high-school broadcasts released CC0 1.0 on the Internet Archive. They show students and school marks; the marks are the schools', not ours, and CC0 does not cover trademarks. We mute the original commentary in everything we publish, use no close-ups, and mask the score box on every thumbnail on this page except the six crops above.
